<objective>
Give agents and the operator one vetted command for the harnesses that only run on Linux: `tests/run-on-tower.sh <harness>`. It rsyncs the current working tree (uncommitted changes included) to a throwaway directory on tower, builds a throwaway image, runs the named harness in a `--rm` container, prints `PASS <harness>` or `FAIL <harness> (rc=N)`, and always deletes the directory and the image.

Purpose: this Mac has no Docker VM (colima has no instance), so `tests/parallel-sort.sh` and the three `tests/unraid-*.sh` harnesses cannot run here at all. Without a sanctioned helper, each future phase improvises its own tower command — and an improvised command on the production NAS is exactly how a live container gets stopped by accident. The helper is the safety rail as much as the convenience (D-07, D-08, D-09).

Output: `tests/run-on-tower.sh`, its documentation in two places, and a recorded baseline `PASS` from both `unraid-healthcheck` and `parallel-sort`.
</objective>

<interfaces>
Contract the helper must implement (D-07, D-08) — treat this as the spec:

    tests/run-on-tower.sh <parallel-sort|unraid-healthcheck|unraid-backup|unraid-fixperms>

    env TOWER      default root@10.0.0.100
    env TOWER_TMP  default /tmp

    id="$(git rev-parse --short HEAD)-$$"
    dir="$TOWER_TMP/gsd-test-$id"
    tag="camera-sorter:gsd-test-$id"

    1. rsync -a --delete \
         --exclude .git --exclude .planning --exclude .impeccable \
         --exclude '__pycache__' --exclude '.pytest_cache' --exclude '.ruff_cache' --exclude '.venv*' \
         ./ "$TOWER:$dir/"
    2. ssh -o BatchMode=yes "$TOWER" "docker build -q -t $tag $dir"
    3a. parallel-sort:
         ssh "$TOWER" "docker run --rm --entrypoint /bin/bash -e SORTER_UNDER_TEST=/sort.sh -v $dir:/work:ro $tag /work/tests/parallel-sort.sh"
    3b. unraid-*:
         ssh "$TOWER" "cd $dir && TEST_IMAGE=$tag tests/<harness>.sh"
    4. trap on EXIT: ssh "$TOWER" "docker rmi -f $tag >/dev/null 2>&1; rm -rf $dir"
    5. exit status is the harness's; last line printed is
       "PASS <harness>"  or  "FAIL <harness> (rc=N)"

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
