**Run this phase with `/gsd-execute-phase 4 --interactive`.** Every tower-mutating command sits inside a `checkpoint:human-verify` task and runs only after the operator types "approved". This phase deliberately overrides the project's `workflow.human_verify_mode=end-of-phase` setting, per ROADMAP Phase 4 § Mode and 04-CONTEXT.md D-13: a container swap is not reversible by an agent, so approval must precede the command, not follow the phase.

**On the task count:** this plan carries nine tasks rather than the usual two or three. Each is a single command plus reading its output — a few percent of context each — and the total is well inside budget. They are not split across plans because rollback state (which container is renamed to what, under which `TAG`) lives in the operator's working memory; a context boundary between "sorter swapped" and "panel swapped" is exactly where a half-deployed production host gets stranded.
</objective>
