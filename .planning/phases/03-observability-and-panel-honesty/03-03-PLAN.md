<objective>
Make a mirror failure diagnosable from the log alone.

On 2026-08-23 the Frame.io mirror logged `Reconcile listing failed: ` with
nothing after the colon. The cause was an httpx timeout: `str(httpx.ReadTimeout(""))`
is the empty string, so `log.error("...: %s", exc)` renders a blank. Two log
sites — the reconcile listing handler and the Telegram send handler — swallow the
one fact that would have identified the failure in seconds.

CONVENTIONS.md § Python already mandates the fix ("log exceptions as `%s: %r`
with `type(exc).__name__` so empty-message exceptions stay diagnosable"); these
two sites predate it.

Purpose: OBS-03.
Output: both log lines carry the class name and the repr, plus two regression
tests that fail today and pass afterwards.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| exception object to log file | An exception raised while talking to Frame.io or Telegram is rendered into a log line an operator reads |
| test process to network | A test that reaches a real HTTP call would hit Frame.io or Telegram for real |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-11 | Information disclosure | `%r` of an exception leaking a bot token or a pre-signed URL into the log | mitigate | Scope the change to exactly the two named sites. Both catch transport exceptions whose `repr` is `ClassName('message')` with no URL: the listing call carries its token in an `Authorization` header, not the path, and the app already routes any URL it logs through the `_safe_url` helper. No other log call is touched, and no site that already passes `exc_info=True` is modified (D-12) |
| T-03-12 | Information disclosure | the dummy `bot_token` in the Telegram test | mitigate | The test sets `app._TG` to a literal placeholder, never reads a real `telegram.json`, and asserts only on the exception class name — never on the token. `app._TG` is restored in a `finally` |
| T-03-13 | Denial of service | a test escaping to the real network | mitigate | Test 1 sets `app._TG = None` so `notify_failure` returns before any POST, and monkeypatches `app.get_token` to raise before the first request. Test 2 monkeypatches `httpx.AsyncClient.post` itself. Both drive coroutines with `asyncio.run`, so nothing outlives the test |
| T-03-14 | Repudiation | a failure that leaves no attributable log record | mitigate | This plan is the mitigation: the class name and repr make an empty-message timeout attributable, and two regression tests keep it that way |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs no packages. The tests deliberately avoid `pytest-asyncio` and use `asyncio.run` with vanilla pytest fixtures so no dependency is added |
</threat_model>
