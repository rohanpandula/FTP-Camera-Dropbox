<objective>
Make every aborted FTP upload reach Telegram exactly once.

`pure-ftpd` is patched to never publish an aborted upload, so a dying Wi-Fi link
today produces silence: no file in `incoming/`, no sorter log line, no alert. The
operator only learns about it by noticing a missing frame days later. This plan
adds a read-only probe to the root cron healthcheck that reads the FTP
container's log, pairs each `451-Transfer aborted` with the `uploaded  (N bytes,
X KB/sec)` NOTICE that precedes it, and sends one Telegram message per new abort,
deduplicated by fingerprint so overlapping cron windows never repeat.

Purpose: OBS-01 — close the one blind spot where a file is lost with no signal.
Output: an abort probe in `contrib/unraid/ftpdropbox-healthcheck.sh`, a `logs`
branch in the docker test stub, and four new harness cases that pass on tower.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pure-ftpd container log → healthcheck parser | Log content is influenced by an unauthenticated FTP client: the filename in a NOTICE line is attacker-chosen |
| healthcheck → Telegram | Parsed, attacker-influenced text leaves the host in an outbound HTTPS POST |
| healthcheck → `${STATE%/*}` | New file written into the root-owned 0700 state directory |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | abort filename in `contrib/unraid/ftpdropbox-healthcheck.sh` | mitigate | Take `${path##*/}` only (never the full path), strip control characters with `tr -d '\000-\037\177'`, truncate to 120 chars, and pass to `tg` which sends via `curl --data-urlencode` — the value never reaches a URL, a shell word, or an `eval` |
| T-03-02 | Information disclosure | `${STATE%/*}/ftp-aborts.seen` | mitigate | Created inside the already-validated root:root 0700 directory with `(umask 077; : > file)`, so it lands 0600; contents are sha256 fingerprints, never filenames or bytes |
| T-03-03 | Denial of service | log read and seen-file growth | mitigate | `docker logs --since "$ABORT_WINDOW"` bounds the read; `ABORT_WINDOW` is charset-validated against `^[0-9]{1,4}[smh]$` and falls back to `15m`; `docker_cmd` already applies `timeout -k 2 $DOCKER_TIMEOUT`; the seen-file is truncated to the last 500 lines after each append |
| T-03-04 | Denial of service | healthcheck exit status | mitigate | The `docker logs` capture is suffixed `|| true` and the block sits mid-script, so a docker failure produces no problem line, no alert, and no change to the exit status (D-04) |
| T-03-05 | Spoofing | a forged `451-Transfer aborted` line in the log | accept | An attacker who can write the FTP container's log already owns the container; worst case is a spurious "re-send it from the card" Telegram message. No destructive action is taken on an abort |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs no packages. Nothing to audit |
</threat_model>
